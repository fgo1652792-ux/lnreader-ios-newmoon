## الدفعة 1 — P0: انهيار القارئ وإعادة التحميل

### 1) إعادة تحميل الفصل عند كل لمسة (السبب الجذري الحقيقي)

سلسلة العطل الكاملة (كل حلقة كانت موثقة في الكود قبل الإصلاح):

```
لمسة على الشاشة → shell يرسل {t:'dock'} → setDockOpen
→ useEffect: StatusBar.setHidden + SystemBars.setHidden
→ iOS يغيّر safe-area insets
→ shellHtml (useMemo) كان يعتمد insets.top/bottom
→ نص HTML جديد → WebView source يتغير
→ إعادة تحميل المستند كاملاً → الفصل يُحمّل من جديد / شاشة سوداء / أزرار ميتة
```

كما كانت ثغرة ثانية: الجسر `NewMoonBridge` يحتفظ بـ `ready=true` بعد أي إعادة تحميل، و`injectJavaScript` يسكُت تماماً إذا لم يكن `window.__wor` موجوداً بعد (أوامر وفصول تضيع بصمت).

الإصلاح:
- `shellHtml` **مجمّد لحظة التركيب** (`mountInsets` يُلتقط مرة واحدة) — نص المستند لا يمكن أن يتغير أثناء الجلسة مهما تكررت اللمسات.
- مناطق الأمان الحيّة تنتقل عبر الجسر كرسالة إعدادات `{safeTop, safeBottom}` — المحرك يعيد كتابة `--wor-safe-top/bottom` في `applyTheme` دون أي إعادة تحميل.
- بروتوكول دورة حياة موثق: `loadStart` (كشف إعادة تحميل حقيقية عبر `bridge.isReady()`) → `ready` (مصافحة كاملة: إعدادات/فصول/كلمات/مفضلة) → `chapter` مع حراسة `chapterSentRef` ضد التكرار.
- `onContentProcessDidTerminate` (iOS) و`onRenderProcessGone` (Android) → `recoverDocument()`: رفع epoch، إلغاء الجلبات العالقة، إعادة تحميل، مصافحة كاملة — هذا يعالج **الشاشة السوداء** الناتجة عن قتل WKWebView لعملية العرض تحت ضغط الذاكرة (iPad 7 ≈ 3GB).
- حارس 30 ثانية: طبقة التحميل لا تحبس القارئ أبداً بعد فشل أو إلغاء.

**اختبار الـ 50 نقرة** (`NewMoonReaderScreen.stability.test.tsx`): يحاكي 50 تبديلة للوحة مع تغيّر insets في كل مرة ويُثبت:
1. نص المستند `source.html` ثابت حرفياً (مقارنة سلاسل) في كل العروض.
2. أمر `chapter` أُرسل **مرة واحدة** بالضبط (صفر تكرار).
3. `reload()` لم يُستدعَ ولا مرة.
4. طبقة التحميل تختفي بعد اكتمال الأنبوب.
5. حالة إضافية: قتل عملية العرض → إعادة تحميل واحدة → مصافحة → فصل جديد أُرسل مرة واحدة إضافية.

> عدد مرات تهيئة WebView قبل الإصلاح: مرة على الأقل لكل نقرة (تتغير insets ⇒ مصدر جديد). بعد الإصلاح: **مرة واحدة لكل جلسة قراءة**، وإعادة واحدة فقط عند قتل عملية العرض الفعلي.

### 2) كراش `FunctionCallException: setActive(undefined)`

```
Calling the 'setActive' function has failed. The 1st argument cannot be cast
to type Bool. Conversion from JavaScript value of type 'undefined' to native
'Bool' failed.
```

التتبع الحرفي للمصدر (بلا تخمين):
- الوحدة الأصلية الوحيدة التي تعرّف `setActive(Bool)` هي `modules/native-volume-button-listener` (Swift `Function("setActive")`).
- المستدعي الوحيد: `src/screens/reader/hooks/useChapter.ts` → `NativeVolumeButtonListener.setActive(useVolumeButtons)`.
- `useVolumeButtons` يأتي من `useChapterGeneralSettings()` التي **لم تكن تدمج** `initialChapterGeneralSettings` مع الكائن المخزّن (بخلاف hooks الأخرى) — أي إعدادات محفوظة من إصدار أقدم تفتقد المفتاح ⇒ القيمة `undefined` ⇒ الكراش عند تركيب القارئ.

الإصلاح: دمج الافتراضيات في كل قراءة (`useChapterGeneralSettings`) + تحويل صريح `!!boolean` في موقع الاستدعاء. اختبار الانحدار يثبت أن كائناً قديماً ناقص المفاتيح (وأخرى تالفة/null) يعيد قيماً منطقية دائماً.

### 3) توحيد إعدادات القارئ (إزالة تضارب المحركين)

- **New Moon هو المحرك الوحيد**: `ReaderScreen` يعرض `NewMoonReaderScreen` دائماً؛ حذف `EngineSelector`؛ القارئ القديم متاح عبر Git فقط.
- حذف معاينة `SettingsReaderWebView` من صفحة إعدادات القارئ، واستبدالها بـ **`WorPreview`**: WebView يشغّل محرك `worShell` الحقيقي بعينة عربية/إنجليزية، يستقبل رقع الإعدادات بنفس بروتوكول القارئ — ما تراه في المعاينة هو ما تقرأ به.
- التبويبات الأربعة أعيد بناؤها على مخزن `@wor_reader_settings_v4` (خط/حجم/تباعد/اتجاه، ألوان/سطوع/شريط تقدم، وضع متتابع/لمس/إبقاء الشاشة/تمرير تلقائي، سرعة وحدّة القراءة الصوتية).
- **ترحيل لمرة واحدة** من إعدادات القارئ القديم مع تحقق نوعي لكل قيمة (أرقام مع تقييد مدى، خطوط بمطابقة قائمة المحرك، ألوان بـ regex سداسي، مطابقة الأنماط الجاهزة) — `settingsMigration.test.ts` يرفض أي payload فاسد.

## الدفعة 2 — أزرار القارئ + RTL

- كل أهداف الدرج مربوطة بشاشات حقيقية: `home`→تبويب المكتبة، `downloads`→شاشة التنزيلات، `settings`→الإعدادات، `about`→حول التطبيق.
- زر «تواصل معنا» **أُزيل من درج المحرك** (خاص بموقع New-moon-2، لا مقابل له في التطبيق) — لا أزرار ميتة.
- RTL نصوص الرواية: `src/utils/textDirection.ts` (كشف الاتجاه بعدّ الأحرف القوية يونيكود) — الوصف والعنوان والمؤلف/الرسام يتبعون **لغة النص** لا لغة الواجهة (عربي = RTL + محاذاة يمين، إنجليزي = LTR) مع دعم المختلط بأغلبية الأحرف.

## الدفعة 3 — «البيانات والتخزين»

- **Swift**: `getStorageInfo` (قياس تكراري دفعة واحدة: سعة الجهاز + أحجام كل فئات حاوية التطبيق)، `getDirectoryStats`، `deleteDirectoryContents` (يمسح المحتويات ويعيد إنشاء المجلد) — كلها **محصورة بإلزامياً داخل حاوية التطبيق** (`PATH_OUTSIDE_CONTAINER` لغير ذلك) بمسح تكراري تراكمي بلا recursion لمئات الفصول.
- **الخدمة**: الفئات القابلة لإعادة البناء قابلة للحذف (فصول، إضافات، صور، نسخ احتياطية مؤقتة، كاش ويب، سجلات أعطال، ملفات مؤقتة)؛ قواعد البيانات (المكتبة/التقدم/الإعدادات) **عرض فقط ولا تُحذف أبداً**؛ كاش الويب محصور بـ `Library/WebKit` — **ملفات تعريف الارتباط وبيانات الدخول لا تُمس**.
- حذف فصول رواية محددة يمر عبر مسار التطبيق القانوني `deleteChapters` (ملفات + أعلام `isDownloaded` في SQLite) ثم **يعيد القياس فعلياً** ويعرض المقدار الحقيقي المحرر مع خطأ صريح `files-remained` إن بقيت ملفات — لا نجاح وهمي.
- الواجهة: بطاقة الجهاز (مستخدم/متاح/إجمالي + بيانات التطبيق المقاسة)، شريط توزيع نسبي، صفوف الفئات، قائمة أحجام الروايات مع حذف لكل رواية.

## الدفعة 4 — «تخصيص المظهر»

- طبقة `customTheme.ts`: تجاوزات ألوان MD3 لكل وضع (فاتح/مظلم منفصلان) مع تحقق سداسي صارم — payload تالف يتراجع إلى «بلا تجاوز» بلا انهيار؛ رياضيات تباين WCAG (حد AA 4.5)؛ ثيمات مسماة محفوظة (حفظ/تطبيق/حذف/تصدير/استيراد JSON).
- التكامل في `useTheme`: التجاوزات تُطبق **قبل** الألوان المحسوبة لتبقى المشتقات متسقة، وتفاعلية عبر MMKV (إعادة فتح التطبيق تحفظها).
- الشاشة: منتقي ألوان تفاعلي لكل رمز، معاينة حية (شريط مكتبة + شبكة روايات + مقطع قراءة RTL + شريط تنقل سفلي) تتحدث مع كل تغيير دون إعادة تصيير كامل للتطبيق، تحذيرات تباين فورية، زر استعادة الافتراضي.

## الدفعة 5 — الهوية

- الشعار الأصلي لموقع قمر الروايات (`New-moon-2/public/icon.png` — هلال وكتاب وريشة) هو مصدر كل الأيقونات: 1024 للمتجر، مدوّرة، splash، adaptive foreground، monochrome.
- `app.json`: الاسم `Moon novels`، الإصدار `2.2.0`، `CFBundleDisplayName` `Moon novels`.
- **`ios.bundleIdentifier` بلا تغيير** عمداً (`com.rajarsheechatterjee.LNReader`) حتى تبقى ترقية التطبيق فوق النسخة المثبتة سليمة بلا فقدان مكتبة/إعدادات — فصل الاسم التجاري عن المعرف التقني.
- شاشة «حول»: صف هوية «قمر الروايات — Moon novels» + رابط مشروع New-moon-2 + **صف النسب والرخص** (LNReader MIT + محرك New-moon-2 — النسب الأصلية محفوظة).
- السلاسل الظاهرة (رسالة إعادة التشغيل، تحذير المستودعات، رسالة الاستعادة بعد الكراش) صارت بالاسم الجديد في العربية والإنجليزية.

## القيود والحدود

1. اختبار المحاكي يعمل على iPad (7th gen)/أحدث iOS runtime متاح على macos-26 — القيد الموثق في الـ workflow: التحقق الفعلي لـ iPadOS 18.5 يكون بـ MinOS≤18.5 + arm64 لأن صورة 18.5 قد لا تتوفر على الآلة.
2. قياسات التخزين تغطي ما يمكن قياسه من حاوية التطبيق فقط؛ أحجام النظام (التطبيق المثبت، كاش النظام) لا تُختلق.
3. أزرار «تواصل» وأدوات المدير والتعليقات والبلاغات أزيلت عمداً — لا يمكن «تشغيلها» دون خادم New-moon-2.
4. قارئ LNReader الكلاسيكي خارج مسار العرض (Git هو مسار الرجوع)؛ شاشة CodeSnippets لا تزال تعرض معاينة القارئ القديم لأكواد CSS/JS القديمة (وظيفة قائمة بذاتها لم تُكسر).
